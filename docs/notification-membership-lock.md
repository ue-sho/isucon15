# 投稿期間開始のusersテーブルロック削減

投稿期間開始の`LOCK TABLE users IN SHARE ROW EXCLUSIVE MODE`を、通知対象の変更とのみ競合するトランザクションadvisory lockへ置き換える。
従来は通常のusers更新や外部キー参照を伴う書き込みも、通知生成が終わるまで待っていた。

- 投稿期間開始は`pg_advisory_xact_lock(20261031, 1)`を排他取得する。
- 登録、地域を指定したプロフィール変更、退会は同じキーを共有取得する。
- 通常のプロフィール変更、画像更新、ログイン、投稿、関係更新はこのロックを取得しない。既存のユーザー行ロックと投稿期間行ロックは維持する。
- すべてusers行のロックより先に取得し、commit/rollbackで自動解放する。登録のユーザー名単位の1引数advisory lockとは別の名前空間を使う。

通知対象の変更は互いに共有できる。期間開始は変更完了を待ってから開始時刻と通知対象を読み取るため、未commitの地域移動や登録を取りこぼさない。開始が先なら対象変更は開始のcommitまで待つ。退会も同じ順序で保護する。
地域ごとの期間開始は引き続き直列化する。地域別ロックへの分割やユーザー行ロックの緩和は今回の範囲に含めない。

登録、地域変更、退会には各1 SQL往復を追加する。初期化・スキーマ・キャッシュ・永続化方式の変更はない。新たな通知対象変更経路を追加する際は同じ共有ロックが必要。

## 検証と反映

使い捨てPostgreSQL 16.11の並行試験で、期間開始中の投稿・ログイン・通常プロフィール変更の進行、登録/地域変更/退会と開始の前後両順序での通知対象、同日付の二重開始の409、投稿と期間切替の排他、失敗時のrollbackを確認した。

本番反映・ベンチのスコア比較は未実施。全アプリの3つの通知対象変更経路と期間開始を同じ版に揃えて反映し、混在中にベンチを実行しない。旧版の地域変更・退会は新しいadvisory lockに参加しない。
戻す場合も全アプリを元の版に揃える。DBマイグレーションやデータ復元は不要。
