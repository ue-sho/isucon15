# 作業メモの入口

準備項目は[Issue #1](https://github.com/ue-sho/isucon15/issues/1)、当日の初動・分担は[Issue #2](https://github.com/ue-sho/isucon15/issues/2)で確認します。docsには、その項目を進める中で調べたこと・試したこと・結果を残します。

目的は、調査した本人以外の2人やAIも、何が分かり、次に何をすればよいか追えるようにすることです。

## 資料の役割

| 場所 | 内容 |
| --- | --- |
| [AGENTS.md](../AGENTS.md) | AIが着手・変更・共有するときに守る方針 |
| このページ | 関係する調査メモを見つける入口と一覧 |
| [メモの雛形](templates/experiment.md) | 一つの調査・改善について記録する項目 |

## メモの使い方

1. 一覧から同じ対象の記録と担当を確認します。
2. 新しい調査は雛形を `docs/experiments/` へコピーし、日付と対象が分かる名前にします。例：`YYYYMMDD-topic.md`。
3. 一覧にリンク・担当・状態を追加し、調査や計測の後に結果と次の一手を更新します。

途中でも、分かったことと未確認のことを残せば引き継げます。試したが採用しなかった案も、理由を記録します。メモの作成だけならベンチは不要です。実際の改善では、その変更に必要な確認を行います。
