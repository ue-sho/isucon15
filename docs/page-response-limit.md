# ページングで返さない51件目のレスポンス生成を省略

2026-10-31、[Issue #25](https://github.com/ue-sho/isucon15/issues/25)。
最新main `cd2be7e` を起点に `perf/page-response-limit` で実装。
#15の投稿ロック変更は含めない。

## 変更

Memories（月・日）、コメント一覧、RealMoji一覧、関係一覧は、SQL取得結果の件数でhasMoreを判定してから50件だけをレスポンス化する。
フィードは権限・種別・推薦順位・カーソルで絞った後の51件目でhasMoreだけを確定し、署名を作らない。
取得SQL・51件取得・並び順・権限・推薦点・画像署名アルゴリズムは変更しない。

次ページがある場合、プロフィール画像付きの投稿・RealMojiでは2署名（HMAC 2000回）、コメント・関係一覧では1署名（1000回）を省く。
プロフィール画像がない場合は削減量が異なり、50件以下のページでは署名削減はない。
Memories内の反応取得数や、推薦フィードの全候補取得を削減する変更ではない。

## 確認

Node.js 26.10.0で型チェックとテストを実行。
DB応答を模擬したAPIテストで、7経路（月・日Memories、コメント、RealMoji、関係一覧、公開フィード、推薦フィード）の0/49/50/51件、同時刻idカーソルによる次ページを確認する。
公開・推薦フィードは権限で落ちる候補を混ぜてもhasMore・件数が変わらないことを確認する。
HMAC呼び出しを数えて返す50件分だけであること、プロフィールURLの署名値が従来の1000回HMACと一致することを確認する。

SQLを変更しておらず、実DBの計画比較は未実施。実ベンチでの署名削減頻度・CPU/p95・スコア改善は未確認。
採点はHTTP成功件数と異なるため、[公式の採点条件](manual-2026-10-31.md#スコアの計算)に従い、ベンチの成否と総スコアで比較する。
デプロイ・再起動・初期化・ベンチは行っていない。
戻す場合は変更コミットをrevertする。DBや永続データの復元は不要。
